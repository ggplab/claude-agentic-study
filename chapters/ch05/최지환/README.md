# CHAPTER 05 — 출력 인터페이스

> 클로드 코드가 **어떻게 응답하고**(출력 스타일), **무엇을 보여 주고**(상태 표시줄), **어떻게 조작되는지**(대화형 모드)를 다룬다. 세 축 모두 결과물의 형태를 사용자가 직접 통제하는 인터페이스다.

> ### 💡 이 장에서 배운 것
> 1. **출력 스타일** — 응답의 형식이 아니라 **시스템 프롬프트 자체**를 교체한다. 그래서 코딩 도구를 문서·교육·분석 도구로 바꿀 수 있다.
> 2. **상태 표시줄** — 클로드가 주는 JSON을 stdin으로 받아 한 줄로 출력한다. 원칙은 하나, **"계산하지 말고 소비하라"**.
> 3. **대화형 모드** — 접두사(`#` `!` `@`)와 단축키로 **컨텍스트를 주입**하고 **되감는다**. 도구를 손에 익히는 만큼 속도가 붙는다.

## 5-1 출력 스타일 커스터마이징

출력 스타일(output style)은 클로드 코드가 응답할 때 따르는 지침의 집합이다. 단순히 형식을 바꾸는 게 아니라 **시스템 프롬프트를 직접 수정**한다. 기본이 아닌 스타일을 고르면 소프트웨어 엔지니어링 지침이 제거되고 사용자가 정의한 지침으로 대체된다. 덕분에 클로드 코드를 기술 문서·교육 콘텐츠·코드 분석 같은 코딩 외 영역으로 확장하면서도, 파일 작업·스크립트 실행 같은 핵심 기능은 유지한다.

> 💡 **핵심** — `CLAUDE.md`가 프로젝트 컨텍스트를, 서브에이전트가 작업 위임을 맡는다면, 출력 스타일은 **결과물이 어떤 톤·형태로 나오는지**를 시스템 프롬프트 수준에서 결정한다.

### 내장 출력 스타일 (4종)

`/config` → **Output style** 메뉴에서 고른다.

| 스타일 | 성격 | 언제 |
|---|---|---|
| **Default** | SWE 최적화, 간결한 응답 | 대부분의 개발 작업 |
| **Proactive** | 묻지 않고 합리적으로 가정해 즉시 실행 | 자율 실행을 원할 때 |
| **Explanatory** | 구현 이유를 교육적으로 함께 설명 | 코드 리뷰·기술 학습 |
| **Learning** | 인사이트 + `TODO(human)`로 일부는 직접 구현 | 손으로 익히는 실습 |

### 바꾸는 법과 저장 위치

`/config`에서 스타일을 고르면 선택은 로컬 설정 `.claude/settings.local.json`에 저장된다(버전 관리에서 제외돼 개발자마다 다르게 쓸 수 있다). 예전 `/output-style` 명령은 v2.1.73에서 폐기 → **v2.1.91에서 제거**됐다(기능 자체는 유지). 출력 스타일은 시스템 프롬프트의 일부라 **세션 시작 시 한 번만 로드**되므로, 바꾼 뒤에는 `/clear`나 새 세션에서 적용된다.

팀 공통 기본값은 공유되는 `.claude/settings.json`의 `outputStyle` 키로 지정한다.

```json
{ "outputStyle": "Explanatory" }
```

> 💡 **핵심** — 전환은 `/config`, 저장은 `settings.local.json`(나만), 팀 기본은 `settings.json`(공유). 바꿔도 안 바뀌면 **`/clear`**.

### 커스텀 스타일 만들기

마크다운 파일 하나 = 프론트매터(메타데이터) + 지침 본문. 저장 위치는 사용자 수준 `~/.claude/output-styles/`(모든 프로젝트) 또는 프로젝트 수준 `.claude/output-styles/`(해당 프로젝트).

```markdown
---
name: korean-architecture-focused
description: 한국어로 응답하며 아키텍처 결정에 집중하는 스타일
keep-coding-instructions: true
---

## 응답 언어
항상 한국어로 응답한다. 기술 용어는 영어 원문 + 한국어 설명.

## 집중 영역
- 아키텍처 결정과 트레이드오프 설명
- 상세한 코드 주석, 디자인 패턴 논의
```

기본적으로 커스텀 스타일은 내장 코딩 지침을 **제거**한다. 코딩은 그대로 시키면서 말투만 바꾸려면 `keep-coding-instructions: true`를 준다(글쓰기·분석 도우미로만 쓸 거면 생략).

> 💡 **핵심** — 커스텀 스타일이 코딩 지침을 **빼 버린다**는 게 함정. 코딩 세션에서 쓸 거면 `keep-coding-instructions: true`가 사실상 필수.

### 다른 기능과의 비교

| 기능 | 동작 | 한마디로 |
|---|---|---|
| **Output Style** | 시스템 프롬프트 **교체** | 어떻게 응답하나 |
| **CLAUDE.md** | 시스템 프롬프트 **추가** | 프로젝트 컨텍스트 |
| **서브에이전트** | 독립 컨텍스트에 위임 | 분리된 작업 실행 |
| **슬래시 명령** | 저장된 프롬프트 실행 | 무슨 작업을 하나 |

> 💡 **핵심** — **Output Style은 "어떻게", 슬래시 명령은 "무엇"**. 둘을 조합하면 특정 스타일로 특정 작업을 수행하는 일관된 워크플로가 된다.

### 환각 방지 지침 (실전)

출력 스타일에 검증 규칙을 심으면 **요청마다 반복하지 않아도 시스템 수준에서** 환각을 줄인다. 정확성이 중요한 기술 문서·API·코드 리뷰에서 특히 차이가 난다. 세 가지 규칙:

1. **출처 없는 URL 금지** — `WebFetch`/`WebSearch`가 실제 반환한 URL만 인용하고, 패턴으로 추측 생성하지 않는다.
2. **확인 없는 버전·API 주장 금지** — 파일 시스템·문서 검색으로 검증한 것만 단정한다.
3. **불확실성 표현 허용** — "검증이 필요합니다" 같은 표현을 명시적으로 열어 둔다.

응답에는 신뢰도와 출처를 붙인다.

```
[검증됨] 도구로 확인함   [가능성 높음] 패턴 기반, 미검증   [불확실] 사용 전 추가 검증
출처 — (파일:줄번호) / (WebFetch URL) / (Context7 라이브러리·버전)
```

팀 표준으로 굳히려면 이 규칙을 담은 스타일을 `.claude/output-styles/`에 두고 커밋한다. (전체 예시는 `code/output-styles/`의 `team-verified-style.md` 참고)

> 💡 **핵심** — 환각 방지는 프롬프트마다 붙이는 게 아니라 **스타일에 한 번** 심어 시스템 수준에서 일관되게 적용한다.

## 5-2 상태 표시줄

상태 표시줄(statusline)은 세션 중 터미널 하단에 뜨는 정보 줄이다. 작동 원리는 단순하다 — 클로드 코드가 **JSON을 stdin으로** 넘기면, 스크립트가 가공해 **한 줄을 stdout으로** 내보낸다.

```
🤖 Opus 4.6 | ☀ v2.1.37 | 💲125/200K | 🀫 R2-D2 | 📊 +0 M171 ?63 | 🌿 main
[모델]        [버전]      [비용]        [출력 스타일]  [깃 상태]      [브랜치]
```

**데이터 흐름 (그림 5-3)**

```
[클로드 코드] ──JSON( model · workspace · cost · context_window … )──▶ stdin
    ──▶ [파싱 + 포매팅 (bash / python / node)] ──▶ stdout ──▶ [터미널 하단 한 줄]
```

전달되는 JSON에는 모델·작업 디렉터리·깃·비용·실행 시간·코드 변경량·컨텍스트 사용률 등이 담긴다. 자주 쓰는 필드만 추리면:

```json
{
  "model": { "display_name": "Opus" },
  "workspace": { "current_dir": "/path/to/project" },
  "cost": { "total_cost_usd": 0.0123, "total_lines_added": 156, "total_lines_removed": 23 },
  "context_window": { "used_percentage": 8 }
}
```

상태 표시줄은 대화가 갱신될 때마다 **최대 300ms 간격**으로 다시 그려진다. 스크립트가 이보다 오래 걸리면 이전 값이 유지되므로 **빠를수록 좋다**.

> 💡 **핵심** — **계산하지 말고 소비하라.** 컨텍스트 사용률·비용은 클로드가 이미 계산해 JSON에 담아 준다. 자체 추정 로직은 유지보수 부채일 뿐이다.

### 설정

`/statusline` 명령으로 안내를 받아 만들거나(추가 지침도 가능: `/statusline 모델 이름을 주황색으로`), `settings.json`에 직접 등록한다. 생성된 스크립트는 `~/.claude/statusline.sh`에 저장되고, 제거는 `/statusline delete`.

```json
{ "statusLine": { "type": "command", "command": "~/.claude/statusline.sh", "padding": 0 } }
```

### 스크립트: 기본형과 델타

가장 단순한 형태 — 모델 이름과 디렉터리만. 이후 모든 스크립트는 이 골격(**stdin 읽기 → `jq`로 추출 → `echo`**)의 변형이다.

```bash
#!/bin/bash
input=$(cat)                                           # stdin에서 JSON 읽기
MODEL=$(echo "$input" | jq -r '.model.display_name')
DIR=$(echo "$input" | jq -r '.workspace.current_dir')
echo "[$MODEL] ${DIR##*/}"                             # ${DIR##*/} = 경로의 마지막 조각
```

생성 후 실행 권한: `chmod +x ~/.claude/statusline.sh`. 여기에 필요한 것만 얹으면 된다 (전체 실행본은 `code/` 폴더):

- **깃 브랜치** — repo인지 먼저 확인해 비-git 디렉터리에서 나는 에러를 막는다.
  ```bash
  if git rev-parse --git-dir >/dev/null 2>&1; then
      BRANCH=$(git branch --show-current 2>/dev/null)
      [ -n "$BRANCH" ] && echo -n " | $BRANCH"
  fi
  ```
- **비용·변경량** — `.cost`에서 뽑아 붙인다: `$(printf '%.4f' "$COST")`, `+$LINES_ADDED -$LINES_REMOVED`.
- **ANSI 색상** — `RED='\033[0;31m'`처럼 정의하고 반드시 `echo -e`로 출력해야 이스케이프가 해석된다. 추가는 녹색, 삭제는 빨강으로.
- **캐싱** — 깃 조회처럼 비싼 작업은 `/tmp`에 **5초 TTL**로 캐싱한다. 자주 실행되니 최적화가 곧 반응성이다.
- **헬퍼 함수** — 필드 추출을 `get_model_name()` 등으로 감싸면 항목을 추가·변경할 때 유지보수가 쉬워진다.

언어는 자유다. **파이썬**은 `json.load(sys.stdin)`으로 바로 파싱하고, 깃 브랜치는 `.git/HEAD`를 직접 읽어 `git` 실행보다 빠르게 얻는다. **Node.js**는 stdin을 이벤트로 모아 `JSON.parse`한다. (`statusline.py`·`statusline.js` 전체는 `code/` 폴더)

> 💡 **핵심** — 골격은 하나(stdin → 추출 → 출력). 브랜치·비용·색·캐시는 그 위에 얹는 델타일 뿐이다. 비싼 조회는 캐싱, 색은 `echo -e`.

### 문제 해결

안 보이면 순서대로 확인한다 — ① 실행 권한(`chmod +x`) → ② **stdout**으로 출력하는지(stderr는 안 뜬다) → ③ `jq` 설치(`brew install jq`). 수동 테스트는 목 JSON을 파이프로 흘려본다.

```bash
echo '{"model":{"display_name":"Test"},"workspace":{"current_dir":"/test"}}' | ./statusline.sh
```

## 5-3 대화형 모드

키보드 단축키와 입력 접두사로 클로드 코드를 빠르게 조작한다.

### 빠른 명령 접두사

| 접두사 | 기능 | 효과 |
|---|---|---|
| `#` | 메모리 | 입력이 `CLAUDE.md`에 기록돼 이후 세션에서도 참조된다 |
| `/` | 슬래시 명령 | `/help` `/clear` `/config` 및 커스텀 명령 호출 |
| `!` | Bash 모드 | 승인 없이 셸을 실행하고 **출력을 컨텍스트에 추가** |
| `@` | 파일 멘션 | 경로 자동완성으로 파일을 컨텍스트에 포함 |

`!`의 핵심은 결과가 컨텍스트에 남는다는 점이다 — `!git status` 실행 후 "이 상태로 커밋 메시지 써 줘"로 이어진다.

> 💡 **핵심** — `@`와 `!`는 **컨텍스트 주입** 도구. 작업을 시키기 전에 현재 상태부터 클로드에게 보여 주면 정확도가 오른다.

### 자주 쓰는 단축키

| 단축키 | 동작 |
|---|---|
| `Ctrl+C` / `Ctrl+D` | 현재 입력·생성 취소 / 세션 종료(EOF) |
| `Ctrl+L` | 화면 지우기(대화 기록은 유지) |
| `Ctrl+O` | 상세 출력 토글(도구 사용·실행 표시) |
| `Ctrl+R` | 역방향 명령 기록 검색(디렉터리별 저장) |
| `Ctrl+B` | 현재 Bash를 백그라운드로 (Tmux는 두 번) |
| `Ctrl+T` | 태스크 목록 토글(팀 모드의 공유 태스크) |
| `Esc Esc` | 코드·대화를 이전 지점으로 되감기(체크포인트) |
| `Tab` | 확장 사고 토글 |
| `Shift+Tab` (또는 `Alt+M`) | 권한 모드 전환(자동 수락·계획·일반) |
| `↑` / `↓` | 명령 기록 탐색 |
| `Ctrl+V` (mac/리눅스) · `Alt+V` (윈도우) | 클립보드 이미지 붙여넣기 |

**여러 줄 입력** — 백슬래시 `\` + `Enter`(모든 터미널), macOS `Option+Enter`, `/terminal-setup` 후 `Shift+Enter`, 또는 그냥 붙여넣기.

### 백그라운드 Bash와 이미지

**백그라운드 Bash**(`Ctrl+B` 또는 직접 요청)는 빌드·테스트·개발 서버 같은 장기 실행을 비동기로 돌리고, 그동안 다른 파일을 분석하게 한다. 출력은 버퍼링돼 `BashOutput`으로 나중에 회수하며, 세션을 끄면 프로세스도 종료된다.

**이미지**는 `Ctrl+V`(mac/리눅스) / `Alt+V`(윈도우)로 붙여 넣는다. 에러 스크린샷·UI 목업처럼 텍스트로 설명하기 어려운 걸 한 장으로 전달 — 디버깅에 특히 유용하다.

### 대화 흐름 4원칙

1. **컨텍스트 먼저** — `@`·`!`로 현재 상태를 알린 뒤 작업을 요청하면 결과가 정확해진다.
2. **작게 쪼갠다** — "전체 리팩터링" 대신 "`src/utils` 구조부터 분석". 응답을 보며 방향을 조정한다.
3. **피드백 루프** — 기대와 다르면 즉시 수정 요청하고, 어긋난 변경은 `Esc Esc`로 되감는다.
4. **확장 사고는 필요할 때만** — 트레이드오프 분석이 필요한 복잡한 작업엔 `Tab`, 단순 작업엔 기본 모드가 더 효율적이다.

> 💡 **핵심** — 컨텍스트 주입(`@`/`!`) → 작게 쪼개기 → 안 되면 `Esc Esc` 되감기. 이 루프가 대화형 모드 생산성의 전부다.

## 마무리

- **출력 스타일** — 시스템 프롬프트를 교체해 응답의 톤·역할을 바꾸고, 환각 방지 규칙을 시스템 수준에 심는다.
- **상태 표시줄** — JSON을 받아 한 줄로 내보내되, 계산은 클로드에게 맡기고 스크립트는 소비만 한다.
- **대화형 모드** — 접두사와 단축키로 컨텍스트를 주입하고 되감으며 대화 흐름을 설계한다.

6장에서는 컨텍스트 유지를 위한 메모리·세션 관리를 다룬다 — `CLAUDE.md` 계층 메모리, 모듈형 임포트, 체크포인팅(`/rewind`)과 깃을 결합한 복구 전략.

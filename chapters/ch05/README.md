# CHAPTER 05 — 출력과 인터페이스

> 클로드 코드가 응답하는 방식을 결정하는 출력 인터페이스에 대해 살펴본다. 시스템 프롬프트를 변경하여 응답의 톤과 형식을 제어하고, 헤더 방지 및 실시간으로 시각화하는 상태 표시줄, 다양한 대화형 모드를 학습한다. 나아가 세션 정보를 실시간으로 시각화하는 상태 표시줄 구성 방법과 대화형 모드를 활용하여 직접 생산성을 극대화하는 실전 패턴을 익힌다.

**리드**: 최지환

에이전트에서 Output Style은 ‘AI가 어떻게 말할지’를 정하는 기능이 아니라, ‘작업 결과를 어떤 신뢰 구조로 보고할지’를 정하는 규칙(출력 계약)이다.
## 에이전트 설계의 3층 구조

에이전트를 프로젝트에 적용할 때는 다음 3층으로 나누어 볼 수 있다.

| 구분                   | 의미                | 예시                           |
| -------------------- | ----------------- | ---------------------------- |
| **Capability Layer** | 무엇을 할 수 있는가       | 파일 읽기, 코드 수정, 검색, 요약, 테스트 실행 |
| **Control Layer**    | 무엇을 허용하거나 차단할 것인가 | Hook, 테스트, 승인, 권한, CI, 실행 제한 |
| **Output Contract**  | 어떻게 보고할 것인가       | 검증됨/불확실, 변경사항, 리스크, 다음 행동    |

이를 한 문장으로 표현하면 다음과 같다.

```text
Agent = Capability Layer + Control Layer + Output Contract
```

이 구조에서 Output Style은 세 번째 층인 **Output Contract**와 연결된다.

## 예시 : 
```
#### 작업 결과
[검증됨] `src/config.ts`에서 API endpoint 설정을 수정했습니다.  
[검증됨] 기존 `v1` 경로를 `v2` 경로로 변경했습니다.  

#### 변경 이유
[검증됨] 현재 호출 함수가 `v2` 스펙을 기준으로 작성되어 있었지만, 설정값은 여전히 `v1`을 바라보고 있었습니다.

#### 테스트
[검증됨] `npm test`를 실행했고, 전체 테스트가 통과했습니다.  

#### 남은 리스크
[불확실] 실제 운영 API 응답은 로컬 테스트에서 확인하지 못했습니다.  
운영 배포 전 staging 환경에서 한 번 더 확인이 필요합니다.

#### 다음 행동
staging 환경에서 API 응답을 확인한 뒤 배포를 승인하는 것이 좋습니다.
```

### 임정 — output style: 명령은 사라지고 설정·체계로 남았다
- **내용 리마인드**: `/output-style` 명령은 v2.1.73에서 deprecated, v2.1.91에서 제거됐다. 기능 자체는 유지되며 `/config` 메뉴 또는 settings의 `outputStyle` 필드로 접근한다. output style은 CLAUDE.md와 달리 시스템 프롬프트 자체를 교체하고, 세션 시작 시 고정된다(프롬프트 캐싱).
- **나에게 어떤 의미였나**: 내 환경은 outputStyle 키 없이 Default로 돌고 있었다. 대신 `~/.claude/rules/`(writing-style·content-creation)와 산출물 포맷 규칙이 사실상의 커스텀 output style 역할을 한다. 이 기회에 내 산출물 5종 인식을 실측으로 검증했더니 3계층 15채널이었다. 정리본: [임정/README.md](임정/README.md)

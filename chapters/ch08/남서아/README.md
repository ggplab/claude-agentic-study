# 남서아 · 8장 정리: 하네스 7요소와 헤르메스 적용 (2026-07-26)

8장은 하네스 엔지니어링을 다룬다. 바이브코딩이 AI에 코드 작성을 요청하는 것이라면, 하네스 엔지니어링은 AI가 올바르게 작동할 수밖에 없는 환경을 만드는 것이다. 나는 그 환경을 이루는 7가지 요소가 각각 뭔지, MoAI-ADK 말고는 누가 어떻게 구현했는지 조사했고, 마지막으로 내가 배포 중인 헤르메스 에이전트에 대입해봤다.

## 1. 하네스 7요소 — 각각 뭐고 왜 필요한가

1. **자기검증 루프** — AI가 작업 결과를 스스로 검사하고, 틀렸으면 다시 고치게 하는 장치. AI는 자기가 뭘 깨뜨렸는지 모른 채 "다 됐다"고 말하기 때문에 필요하다.
2. **컨텍스트 맵** — 프로젝트 전체 구조를 요약한 지도를 AI에게 주는 것. 파일 하나만 보고 고치다가 연결된 다른 곳을 깨뜨리는 사고를 막는다.
3. **세션 지속성** — 대화가 끝나거나 끊겨도 진행 상황과 결정이 남아서, 다음 세션이 이어받게 하는 것. 매번 처음부터 다시 설명하는 비용을 없앤다.
4. **실패 체크리스트** — AI가 반복하는 실수를 목록으로 만들어 매번 참조하게 하는 것. 같은 사고가 두 번 나지 않게 한다.
5. **언어 독립성** — 하네스가 특정 프로그래밍 언어에 묶이지 않게 하는 것. 언어를 바꿀 때마다 하네스를 새로 만들지 않아도 된다.
6. **가비지 컬렉션** — 쓸모없어진 코드·파일·컨텍스트를 정기적으로 치우는 것. AI는 만들다 버린 흔적을 스스로 치우지 않는다.
7. **스캐폴딩 우선** — 빈 화면에서 자유롭게 짓게 하지 않고, 틀을 먼저 깔고 그 안을 채우게 하는 것. 결과물이 예측 가능해진다.

## 2. MoAI-ADK 밖의 구현들 — 조사해보니

7요소는 MoAI-ADK만의 개념이 아니고 요소마다 오픈소스 구현이 있다. 다만 조사해보니 대부분은 Aider, OpenHands 같은 별도의 대형 코딩 도구라서, 내 상황(헤르메스가 Codex에 코딩을 위임하는 구조)에 갖다 쓰기는 어려웠다. 실제로 쓸 만한 건 작고 단순한 것들이었다:

- [Repomix](https://github.com/yamadashy/repomix) — 레포 전체를 AI에 주기 좋은 한 파일로 묶어준다. 코드 지도(②) 초안 뽑는 데 바로 쓸 수 있다.
- [pre-commit](https://github.com/pre-commit/pre-commit) — 커밋 직전에 검사를 강제로 돌려 실패하면 커밋을 막는다. 어떤 코딩 도구를 쓰든 git 수준에서 동작한다.
- [Vulture](https://github.com/jendrikseipp/vulture) — 파이썬 죽은 코드 탐지. (비슷한 Knip은 JS/TS 전용이라 파이썬 킷엔 해당 없음)
- ponytail 플러그인 — 요청 안 한 추상화 금지, 최소한의 해법 강제. 실패 체크리스트(④) 계열이고, 헤르메스 SOUL에도 위임 시 이 원칙을 붙이라는 규칙이 이미 들어 있다.

실패 체크리스트와 가비지 컬렉션은 그 이름을 내건 유명 레포가 아직 없고, 위처럼 인접 도구를 조합해 쓰는 게 현재 답이다.

## 3. 헤르메스에 대입

배경: 헤르메스를 비기술직군 사람들에게 깔아주고 있는데, 자기개선루프가 완성된 스크립트의 맥락을 잃고 기존 코드를 부수는 일이 실제로 있었다.

킷을 열어보면 위키(기억), 정리 스크립트(청소), 템플릿 구조(틀) 같은 장치가 이미 있어서 언뜻 하네스가 갖춰진 것처럼 보인다. 하지만 이건 구직 파이프라인이라는 업무를 위한 장치지, 코딩 작업용 하네스가 아니다. 헤르메스가 코딩을 하는 순간 — 자기 기능을 만들거나 스스로를 고칠 때 — 은 아무 장치 없이 맨몸으로 한다. 점검 스크립트가 있어도 사람이 직접 돌려야 하고, 자기 코드가 서로 어떻게 얽혀 있는지 적힌 지도도 없다. 사고가 거기서 난 이유다.

그래서 할 일은 7개 이식이 아니라 자기수정 경로에 4개를 거는 것이다:

1. **자기수정 게이트** — 자기 파일을 고칠 땐 수정 전 git으로 상태 저장 → 고치기 → 점검 스크립트 통과 확인 → 실패하면 되돌리기. 재료는 킷에 다 있고 연결만 하면 된다.
2. **코어 동결** — 새 기능은 plugins 폴더로만 추가하고 핵심 파일은 자기수정 금지. 최악의 경우에도 플러그인 하나 지우면 복구된다.
3. **실패 체크리스트** — 이번 사고부터 위키에 쌓고, 자기수정 프롬프트가 반드시 읽게 한다.
4. **코드 지도** — 스크립트들의 역할·의존관계를 적은 문서 하나. Repomix로 초안을 뽑으면 된다.

## 4. 코딩을 위임할 때 바로 쓸 수 있는 것들 (Codex 기준)

헤르메스는 코딩을 Codex CLI에 위임하니까, 클로드 코드 전용 플러그인 말고 Codex에서도 되는 것들을 찾아봤다. 전부 설치가 명령 한 줄이거나 설정 파일 하나 수준이다.

- **Codex 자체 설정** — `~/.codex/config.toml`에 [승인 정책과 샌드박스](https://developers.openai.com/codex/cli)를 정할 수 있다. `sandbox_mode = "workspace-write"`로 두면 작업 폴더 밖은 못 건드린다. 설치할 것도 없이 설정 두 줄이다.
- **[AGENTS.md](https://agents.md/)** — 도구 불문 규칙 파일 표준. 클로드 코드의 CLAUDE.md 같은 걸 Codex·Cursor 등 어디서나 읽게 한 것이다. Codex가 네이티브로 지원한다. 규칙 내용은 [awesome-cursorrules](https://github.com/PatrickJS/awesome-cursorrules) 모음에서 스택 맞는 걸 복붙하면 된다.
- **[pre-commit](https://pre-commit.com)** — `pip install pre-commit` 후 설정 파일 하나. 시크릿 커밋, main 직접 커밋, 검사 실패 코드를 커밋 시점에 기계로 막는다. 에이전트가 뭘 쓰든 git 수준에서 걸린다.
- **git 스냅샷 패턴** — 별도 도구 없이 위임 스크립트에 세 줄 넣으면 된다: 작업 전 `git add -A && git commit -m wip`(또는 `git stash push -u`)로 상태를 저장하고, 작업 후 점검이 실패하면 `git reset --hard`로 되돌린다. 내가 만들려는 "저장→수정→실패 시 복원"이 이거다.
- **[Repomix](https://github.com/yamadashy/repomix)** — `npx repomix` 한 줄로 레포 전체를 텍스트 한 파일로 묶는다. 출력이 그냥 텍스트라 Codex 세션 첫 컨텍스트로 바로 넣을 수 있다.

적용 순서로 치면: Codex 설정 두 줄 → AGENTS.md 하나 → pre-commit → git 스냅샷 패턴 → (큰 레포면) Repomix. 참고로 Gemini CLI는 파일 수정 전 자동 스냅샷이 내장인데 Codex엔 없어서, 스냅샷은 저 패턴으로 직접 넣어야 한다.

## 5. MoAI를 그냥 깔면 안 되나

안 된다. MoAI는 개발자가 클로드 코드로 코딩할 때 쓰는 하네스라, 헤르메스가 런타임에 스스로를 고치는 경로엔 끼어들 자리가 없다. 헤르메스 크론의 provider도 GPT라 클로드 코드 전용인 MoAI와 결합되지 않는다. 필요한 건 위 1·2번 정도로 작다. MoAI를 까는 게 아니라 그 발상을 옮겨 심는 것이다.

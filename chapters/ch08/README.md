### 임정 — '강제'의 실체 감별법: 지시문 게이트 vs 기계 게이트
- **내용 리마인드**: 하네스가 "규칙을 강제한다"고 말할 때, 실제로 기계가 막는 것과 프롬프트로 부탁하는 것은 다름. MoAI-ADK를 책 출간 시점 태그(v2.14.0)로 직접 열어보면 TRUST-5 중 기계가 차단하는 건 2개(LSP·정적분석)뿐이고, 간판 격인 TDD 강제는 훅 핸들러가 `// TODO` 미구현 스텁이라 무엇을 넣어도 통과. 커버리지 85%도 CI 게이트가 아니라 리포트 업로드만
- **나에게 어떤 의미였나**: 같은 감별법을 내 환경에 대니 훅 10개가 전부 주입·경고·기록형이고 차단형이 0개라는 게 드러남. 기계가 막는 건 permissions deny 21항목뿐. 5축(명세·게이트·라우팅·문서동기화·추적성) 대조 결과 충족 3·공백 2로, 공백을 메우는 도입 제안 3개까지 정리. 상세: [임정/README.md](임정/README.md)

### 남서아 — 하네스 엔지니어링: AI가 올바르게 작동할 수밖에 없는 환경
- **내용 리마인드**: 바이브코딩이 AI에게 코드 작성을 요청하는 것이라면, 하네스 엔지니어링은 AI가 **올바르게 작동할 수밖에 없는 환경**을 구축하는 것이다. MoAI-ADK는 그 환경을 구성하는 도구 중 하나로, 책 시점(v2.14.0) 기준 하네스를 7가지로 구성한다 — 자기검증 루프, 컨텍스트 맵, 세션 지속성, 실패 체크리스트, 언어 독립성, 가비지 컬렉션, 스캐폴딩 우선. 파이프라인은 plan(SPEC 작성) → run(TDD/DDD 구현) → sync(문서 동기화) 3단계이고, 오케스트레이터 MoAI가 manager 계열 전문 에이전트를 자동 배치한다(자동위임). 이 모든 것은 Go로 작성된 `moai` CLI 바이너리로 실행된다. 단, 임정의 실측이 보여주듯 책 시점의 "품질 게이트 강제"는 상당 부분 지시문 수준이었다(기계 차단은 LSP·정적분석 2개뿐) — 하네스는 **표방과 실체를 구분해서** 봐야 한다.
- **나에게 어떤 의미였나**: 하네스의 필요성에 크게 공감했다. 요즘 헤르메스 에이전트를 세일즈·마케팅 등 비기술직군 동료들에게 깔아주고 있는데, 그중 헤르메스가 이미 완성된 스크립트 로직에 자기개선루프를 적용하다 **맥락 유실·기존 코드 파괴**를 일으켜 골치를 앓는 친구가 있었다. 이건 출판사 소개문이 꼽은 바이브코딩의 한계("맥락 유실, 품질의 비결정성, 기존 코드 파괴")와 문자 그대로 일치한다 — 책의 문제의식을 실사용자가 재현한 셈. 그래서 헤르메스가 자기 기능을 작성·수정할 때 이런 검증 루프·하네스를 씌우는 실험을 해보려 한다(클로드 코드/Codex에게 코딩을 위임하는 모드 포함). 임정이 하네스를 **만든 쪽**의 강제 실체를 감별했다면, 나는 **받는 쪽** — 배포된 에이전트의 자기수정에 하네스를 씌우는 관점이다. (상세: [남서아/README.md](남서아/README.md) — 7요소별 대체 구현 레포 지도 + 헤르메스 대입)

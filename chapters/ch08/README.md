### 임정 — '강제'의 실체 감별법: 지시문 게이트 vs 기계 게이트
- **내용 리마인드**: 하네스가 "규칙을 강제한다"고 말할 때, 실제로 기계가 막는 것과 프롬프트로 부탁하는 것은 다름. MoAI-ADK를 책 출간 시점 태그(v2.14.0)로 직접 열어보면 TRUST-5 중 기계가 차단하는 건 2개(LSP·정적분석)뿐이고, 간판 격인 TDD 강제는 훅 핸들러가 `// TODO` 미구현 스텁이라 무엇을 넣어도 통과. 커버리지 85%도 CI 게이트가 아니라 리포트 업로드만
- **나에게 어떤 의미였나**: 같은 감별법을 내 환경에 대니 훅 10개가 전부 주입·경고·기록형이고 차단형이 0개라는 게 드러남. 기계가 막는 건 permissions deny 21항목뿐. 5축(명세·게이트·라우팅·문서동기화·추적성) 대조 결과 충족 3·공백 2로, 공백을 메우는 도입 제안 3개까지 정리. 상세: [임정/README.md](임정/README.md)

### 남서아 — 하네스 엔지니어링: AI가 올바르게 작동할 수밖에 없는 환경
- **내용 리마인드**: 바이브코딩이 AI에 코드 작성을 요청하는 것이라면, 하네스 엔지니어링은 AI가 올바르게 작동할 수밖에 없는 환경을 구축하는 것이다. MoAI-ADK는 이 환경을 구성하는 도구 중 하나다. 하네스는 자기검증 루프, 컨텍스트 맵, 세션 지속성, 실패 체크리스트, 언어 독립성, 가비지 컬렉션, 스캐폴딩 우선의 7가지로 구성된다. MoAI-ADK는 plan(SPEC 작성) → run(TDD/DDD 구현) → sync(문서 동기화) 파이프라인을 쓰며, 오케스트레이터 MoAI가 전문 에이전트들을 자동 배치해 중간 조율한다.
- **나에게 어떤 의미였나**: 하네스 엔지니어링의 필요성에 매우 공감하게 되는 내용이었다. 요즘 헤르메스 에이전트를 세일즈·마케팅 같은 비기술직군 사람들에게 깔아주고 있는데, 헤르메스가 이미 완성된 스크립트 로직에 자기개선루프를 돌리다 맥락을 잃고 기존 코드를 부수는 문제로 골치를 앓는 친구가 있었다. 책이 말하는 바이브코딩의 한계 그대로였다. 그래서 헤르메스가 자체 기능을 만들거나 스스로를 수정할 때 이런 검증 루프·하네스를 씌워보려 한다. 클로드 코드/Codex에 코딩을 위임하는 모드와 함께 실험해볼 생각이다. (상세: [남서아/README.md](남서아/README.md) — 7요소별 대체 구현 레포 지도 + 헤르메스 대입)

### 문종운 — 세션은 사라진다: 무엇이 `/compact`를 살아남는가
- **내용 리마인드**: 메모리를 "4계층 표"가 아니라 **실행 시점의 생존 관점**으로 본다. `/compact`는 대화를 요약해 컨텍스트만 비우는데, 이때 **디스크에 있는 것은 재주입되고(루트 CLAUDE.md, auto memory) 대화에만 있던 것은 사라진다**. 특히 **하위 디렉터리 `CLAUDE.md`와 `paths:` 붙은 rules는 소실**된다 — 긴 세션 후반부에 규칙이 조용히 안 지켜지는 이유. 또한 우선순위는 override가 아니라 **concat**(전부 이어붙음)이라, 모순된 규칙을 여러 계층에 두면 클로드가 임의로 고른다.
- **나에게 어떤 의미였나**: 실측해보니 내 `~/.claude/CLAUDE.md`(60줄)·`./CLAUDE.md`(38줄)는 200줄 규격을 통과했지만 **`@import`를 하나도 안 쓰고 있었다**(마크다운 링크를 import로 착각). auto memory는 프로젝트 스코프에만 있고(MEMORY.md 6줄/794B, 한도의 3%), 그중 `skill-create-bundle-wip.md`는 **이미 커밋됐는데 이름이 여전히 WIP** — 정리 대상 1호. 세션은 `~/.claude/projects/<slug>/*.jsonl`에 10개(전체 50MB), `cleanupPeriodDays` 미설정으로 **기본 30일** — 주 1회 스터디엔 아슬아슬해서 늘릴지 고민 중. 정리본: [문종운/README.md](문종운/README.md)

### 남서아 — CLAUDE.md vs `.claude/rules/`: 무엇을 기억할 것인가 / 언제 어떤 지침을 적용할 것인가
- **내용 리마인드**: 둘 다 지침 파일인데 축이 다르다. CLAUDE.md는 **"무엇을 항상 기억할 것인가"** — 매 세션 전문이 로드되고, 디렉토리 트리를 따라 올라가며 발견된 파일이 전부 이어붙는다(concat, override 아님). `@path` import로 모듈화할 수 있지만 import된 파일도 시작 시 전부 로드돼 컨텍스트 절약은 안 된다(정리용). 반면 `.claude/rules/`는 **"언제 어떤 지침을 적용할 것인가"** — 주제별 파일로 쪼개고, frontmatter `paths:` glob을 붙이면 클로드가 **매칭되는 파일을 읽을 때만** 로드된다(선택적 로드). paths 없는 rule은 시작 시 로드라 CLAUDE.md와 같다. 그리고 **언로드 규칙은 없다** — 한번 로드된 지침은 `/clear`·`/compact` 전까지 상주하고, 컴팩션 후 재주입되는 건 루트 CLAUDE.md뿐이라(경로 rule은 다음 매칭 read 때 재로드) 언로드는 설계된 기능이 아니라 컨텍스트 수명의 부산물이었다. (종운의 "컴팩션 생존"이 소멸 시점을 본다면, 나는 로드 시점의 설계를 본다)
- **나에게 어떤 의미였나**: 헤르메스 에이전트를 만들면서 SOUL.md 한 파일에 캐릭터·출력 규칙·운영 규칙(위임 게이트, 저장 경로, 탐색 순서)이 전부 들어가는 게 계속 걸렸다 — soul에 못 넣는 것들을 아키텍처 룰이든 뭐든 구분해야 한다고 보고 있었는데, 이 장이 그 구분 기준을 줬다. **"항상 유지할 정체성(=CLAUDE.md/SOUL)"과 "특정 작업에서만 켜질 절차(=paths rule/스킬)"는 다른 파일이어야 한다.** 헤르메스에도 `@` import식 로드와 모듈형 룰 시스템을 옮겨볼 생각이다. 남은 궁금증이었던 언로드는 조사해보니 "없다"가 답이었는데, 이게 오히려 시사점이다 — 선택적 로드만 있고 선택적 언로드가 없으니, 안 쓰는 지침이 세션 내내 컨텍스트를 차지하지 않게 하려면 **애초에 로드 조건(paths·스킬 트리거)을 좁게 설계하는 수밖에 없다**. (상세: [남서아/README.md](남서아/README.md) — 로드 설계 지도 + 헤르메스 분리 설계 · 근거: [공식 memory 문서](https://code.claude.com/docs/en/memory))

② Auto memory — 학습·패턴

CLAUDE.md와 책임이 다르다. 규칙은 CLAUDE.md, 겪어서 알게 된 사실은 memory. 경로는 git 저장소 기준이라 같은 repo의 worktree들이 공유한다.

MEMORY.md = 인덱스
~/.claude/projects/<project>/memory/
세션 시작 시 앞 200줄 또는 25KB만 로드 (먼저 오는 쪽)
내 실측: 6줄 / 794B — 한도의 3%
▼ 필요할 때만 (on-demand)
사실 파일 — 시작 시 로드 안 됨
pages-deploy-permissions.md skill-files-no-hook-bypass.md skill-reviewer-is-plugin-dev-agent.md skill-create-bundle-wip.md
클로드가 인덱스 한 줄을 보고 그때 Read한다 → 그래서 응답이 한 박자 늦다
파일 1개 = 사실 1개(단일 책임) · frontmatter type: user / feedback / project / reference
비대해지면 3중 손해: ① 과거 기억이 현재와 어긋남 ② 컨텍스트 낭비 ③ on-demand Read로 지연

③ /compact 생존표 — 공식 문서 기준

압축은 대화를 요약해 컨텍스트만 비운다(세션은 유지). 이때 디스크에 있는 것은 다시 주입되고, 대화에만 있던 것은 사라진다.

세션은 어디에 쌓이나 — 메모 정정
~/.claude/sessions/는 대화 기록이 아니다. pid·sessionId·cwd만 든 런타임 레지스트리(내 환경 7개 / 28KB).
진짜 transcript는 ~/.claude/projects/<slug>/<session-id>.jsonl — 이 프로젝트만 10개, 전체 50MB.
30일 뒤 지워진다
cleanupPeriodDays 기본 30(최소 1, 0은 오류). 시작할 때 오래된 세션 파일을 지운다.
내 settings.json엔 이 키가 없음 → 기본 30일로 도는 중.
--continue 최근 1개 / --resume 골라서 재개.
병렬 작업: 두 가지 오염을 따로 막는다
파일 오염 → git worktree로 디렉터리를 쪼갠다 (claude --worktree, 공식 권장).
컨텍스트 오염 → 서브에이전트. 각자 독립 컨텍스트에서 일하고 요약만 메인으로 돌려준다.
